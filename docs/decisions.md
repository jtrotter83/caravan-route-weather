# Key Decisions

| #   | Decision                                                                              | Rationale                                                                                                                                                                                        |
| --- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | **Weather-at-ETA, not destination-only**                                              | Core product premise. Waypoints are sampled along the route and matched to the hourly forecast slot nearest their estimated arrival.                                                             |
| 2   | **ETA proportional to distance fraction**                                             | OSRM's demo API gives step timing, but steady-progress interpolation over the simplified geometry is robust and adequate for V1. Revisit with per-step timing if traffic-aware routes are added. |
| 3   | **≤8 waypoints, batched Open-Meteo call**                                             | Open-Meteo accepts comma-separated coordinates returning an array — one request for all waypoints keeps us well inside fair-use limits.                                                          |
| 4   | **Wind in mph, everything else metric**                                               | UK convention: drivers know wind in mph (Met Office warns in mph); temp °C, rain mm, visibility m. The >35 mph gust danger threshold matches common caravan-club guidance; 30 mph is caution.    |
| 5   | **Services behind small interfaces (`Geocoder`, `RoutingService`, `WeatherService`)** | SOLID dependency inversion — UI/hook depend on interfaces, concrete fetchers are injected and trivially mocked in tests. No test ever hits a real API.                                           |
| 6   | **Pure logic modules (`waypoints`, `risk`)**                                          | Distance interpolation, ETA sampling and risk thresholds are pure functions — unit-tested exhaustively without any I/O.                                                                          |
| 7   | **Nominatim debounced 500 ms, ≥3 chars**                                              | Usage-policy compliance; aborts in-flight searches on new input.                                                                                                                                 |
| 8   | **Risk aggregation = worst waypoint wins**                                            | For towing safety, the most dangerous section of the journey defines the trip verdict.                                                                                                           |
| 9   | **Forecast-horizon flag**                                                             | Open-Meteo hourly data spans ~7 days; ETAs near/past the last slot are marked `isProjectedBeyondForecast` and surface a caution rather than silently extrapolating.                              |
| 10  | **Static client-only build (Vite, GitHub Pages base path)**                           | No backend, no keys, free APIs — deployable anywhere static.                                                                                                                                     |
| 11  | **Vitest + RTL, map component stubbed in integration tests**                          | Leaflet needs real layout; jsdom can't host it. The integration test mocks only the map render, everything else (geocoding → routing → weather → risk → UI) runs for real against mocked fetch.  |
